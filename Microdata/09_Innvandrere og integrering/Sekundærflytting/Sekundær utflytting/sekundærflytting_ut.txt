// Formål: Følge flyktninger som fikk sin første bosettingskommune i Telemark
// i løpet av årene x-9 til x-5 (der x = siste tilgjengelige år), med utgangs-
// punkt i bosted per 1.1.(x-5). Vi ser 5 år fram i tid (x) og undersøker om de
// fortsatt bor i samme kommune (bofaste), har flyttet videre - internt i
// Telemark eller ut av fylket (sekundærflytting) - eller er registrert som
// utvandret/død.
//
// Bakgrunn/metodikk: se Fafo-rapport 2025:14, "Flytting etter bosetting"
// (https://www.fafo.no/images/pub/2025/20927.pdf)
//
// Scriptet er bygd med samme mønster (dynamiske årstallparametre via let/$,
// ++ for å bygge årstallspesifikke variabelnavn, for/end-løkker, tabulate/
// sankey for løpende kontroll) som brukes i andre analysescript i dette
// repoet, se f.eks.
// "Microdata/02_Opplæring_og_kompetanse/Analyse 2026/Utenforskap_over_flere_år.txt".
//
// ----------------------------------------------------------------------------
// VIKTIGE ANTAKELSER SOM MÅ VERIFISERES I MICRODATA.NO FØR SCRIPTET TAS I BRUK
// ----------------------------------------------------------------------------
// 1) INTRO_FORST_BOSETTING_KOMMNR viste seg (ved faktisk kjøring) å bare ha
//    bestemte, fastsatte "statusdatoer" tilgjengelig (tidligste 2022-12-31),
//    og kan derfor IKKE brukes til å hente bosted på en valgfri dato tilbake
//    i 2016-2020. Scriptet bruker derfor i stedet BEFOLKNING_FORSTDATO
//    (bosettingsår, STEG 2b) og BEFOLKNING_KOMMNR_FORMELL per 1.1.$aar0
//    (opprinnelig kommune, STEG 1).
//    FORSTDATO importeres som alfanumerisk (streng). Ved faktisk kjøring ga
//    substr() en advarsel om at den forventer et NUMERISK argument - løst
//    ved å destringe FORSTDATO til numerisk FØRST, og hente årstallet med
//    heltallsdivisjon (int(forstdato/10000)) i stedet for substr - se STEG 2b.
//    BEFOLKNING_STATUSKODE per $dato_oppfolging (2025-01-01 med x=2025) er
//    bekreftet å fungere ved faktisk kjøring (til forskjell fra et lignende
//    script fra Trøndelag fylkeskommune, som av ukjent grunn kun hentet
//    denne variabelen per 2024-01-01) - ingen endring nødvendig i STEG 4.
// 2) Flyktningbakgrunn identifiseres via BEFOLKNING_INNGRUNN1 == 'FLU' alene
//    (bekreftet kodeverdi) - se STEG 2a. Et separat filter på BEFOLKNING_
//    INVKAT == 'B' (innvandrer) er bevisst IKKE brukt: INNGRUNN1 er per
//    definisjon bare populert for innvandrere, så et slikt filter ville vært
//    redundant (samme tilnærming som i et tilsvarende script fra Trøndelag
//    fylkeskommune, som heller ikke filtrerer på INVKAT).
//    NB: INNGRUNN1 er en FIXED-variabel og spenner derfor i utgangspunktet
//    over hele det historiske befolkningsregisteret (også døde/utvandrede) -
//    dette er uten betydning her, siden bostedskommune (en STATUS-variabel)
//    allerede er importert FØRST i STEG 1 og dermed avgrenser populasjonen
//    til de som var i live og registrert bosatt i Telemark per $dato_aar0,
//    før flyktningfilteret i det hele tatt anvendes.
//    Bekreftet dekningsforskjell: INVKAT dekker alle innvandrere tilbake til
//    1901, mens INNGRUNN1 kun dekker innvandrere med IKKE-nordisk stats-
//    borgerskap bosatt fra og med 1990. Dette er uten betydning for denne
//    analysen: kohorten (bosatt 2016-2020) ligger langt innenfor 1990-
//    grensen, og nordiske statsborgere har i praksis aldri flyktningstatus
//    (fri bevegelse innad i Norden), så avgrensningen til ikke-nordiske
//    statsborgere ekskluderer ingen reelle flyktninger.
// 3) Opprinnelig kommune (STEG 1) er bosted per 1.1.$aar0 (BEFOLKNING_
//    KOMMNR_FORMELL), ikke nødvendigvis nøyaktig kommunen personen faktisk
//    ble bosatt i (disse kan i prinsippet avvike hvis personen flyttet
//    mellom bosettingsdato og 1.1.$aar0) - dette er imidlertid i tråd med
//    oppgavetekstens egen formulering ("ta utgangspunkt i den kommunen de
//    bodde i per 1.1.2020").
// 4) Sentralitets- og kommunenummer-oppslagene (STEG 1 og STEG 4b) er meka-
//    nisk generert fra de vedlagte filene sentralitet.csv og
//    telemark_kommuner.csv, og er ikke i seg selv usikre - men de tabuleres
//    likevel med "missing" underveis, slik at evt. kommunenumre som ikke
//    fanges opp av oppslagene blir synlige.
// 5) Rekkefølgen på STEG 1 og STEG 2 (geografi FØR flyktningstatus) følger
//    samme mønster som Trøndelag fylkeskommune sitt tilsvarende script -
//    mer effektivt enn å filtrere hele landets flyktningpopulasjon FØR man
//    avgrenser til Telemark, siden det gir et mindre datasett å jobbe videre
//    med gjennom resten av scriptet.
// ============================================================================

// aar0 = observasjonsår/basisår. "Opprinnelig" bosettingskommune måles per

// Antall år kohortvinduet dekker (5 år: bosatt i år aar0-4 t.o.m. aar0, dvs.

// oppfolgingsaar = året vi måler bosted 5 år etter (= aar0 + 5 = x).

// dag i $x, IKKE 1. januar. Grunn: hvis vi hadde brukt 1.1.$x (slik

// 2025) rukket å få en registrert Telemark-adresse ennå på den datoen - de

// ----------------------------------------------------------------------------
// FORSTDATO importeres som alfanumerisk (streng, YYYYMMDD). Ved faktisk
// kjøring ga substr(forstdato,...) en advarsel om at funksjonen forventer et
// NUMERISK argument, ikke alfanumerisk - og det påfølgende destring-steget
// bekreftet at resultatet ble feil. Løsning: destring forstdato FØRST (gjør
// den numerisk), og hent årstallet med aritmetikk (heltallsdivisjon) i
// stedet for substr.

// NB: "destring forstdato" gir en advarsel her ("Forventet en numerisk
// variabel, fikk forstdato" / "Konverterte forstdato til en alfanumerisk

// DIAGNOSTIKK: fordeling av bosettingsår FØR kohortvinduet (x-9 til x-5)
// snevrer det inn. NB: siden populasjonen ble definert i STEG 1 via
// BEFOLKNING_KOMMNR_FORMELL per 1.1.$aar0 (en STATUS-variabel evaluert på en
// FAST, tidligere dato), er bosettingsaar her mekanisk begrenset til <=
// omtrent $aar0 for ALLE i datasettet - ingen kan ha bosatt seg etter denne
// datoen og likevel være med i datasettet. Denne tabellen viser derfor bare
// årene FØR $aar0, og er ikke egnet til å sjekke om bosetting har fortsatt
// etter $aar0 (se DEL A øverst i scriptet for en slik sjekk, uavhengig av
// geografifilteret i STEG 1).
tabulate bosettingsaar, missing

// Behold bare de som ble bosatt i løpet av kohortvinduet (x-9 til x-5)
keep if bosettingsaar >= $aar0 - $antall_kohortaar + 1 & bosettingsaar <= $aar0

// Fordeling ETTER at kohortvinduet er anvendt (den faktiske analysepopulasjonen)
tabulate bosettingsaar, missing
