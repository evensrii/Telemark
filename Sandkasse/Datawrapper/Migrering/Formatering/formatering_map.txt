//// Formatting reference: maps, choropleth of the municipalities in Telemark (Datawrapper type "d3-maps-choropleth")

Source: chart 3SHpp ("Andel flyktninger i Telemark"), fetched 2026-11-09 via GET https://api.datawrapper.de/v3/charts/3SHpp
Data at the time: Sandkasse/Datawrapper/Migrering/Dummy data/andel_flyktninger.csv
(columns "Region", "Andel flyktninger 2025", "Label" and "Label+Value"; one row per municipality, plus the rows
"Norge" and "Telemark", which have no area on the map and are ignored)

This file is self-contained: formatering_generelt.txt does NOT apply to maps. Every rule for maps is in this file.

Part 1 is your own rules, written in plain language.
Part 2 is the technical reference: the API keys and values that make 3SHpp look the way it does.
Where they disagree, Part 1 wins.
Keys are set with PATCH https://api.datawrapper.de/v3/charts/{id} and body {"metadata": {...}}.


////////////////////////////////////////////////////////////
//// PART 1: CUSTOM RULES
////////////////////////////////////////////////////////////

// Data layout
One row per municipality. Columns:
- first column (any name: "Region", "Kommune", "Område" ...): the municipality name, matched against the
  names in the map (basemap)
- one value column (e.g. "Andel flyktninger 2025"), used for the colors
- "Label+Value": the text shown on the map, e.g. "Bamble<br>50%" (name and value on two lines).
  Always this column name; the text is made ready (rounding, %) by the query script.
Rows that are not municipalities (e.g. "Norge", "Telemark") may be in the CSV; the map ignores them.

Data files for maps: the "dw_" version of the query script's CSV (e.g. dw_aleneboende.csv next to
aleneboende.csv), made by Helper_scripts/datawrapper_functions.py. The original CSVs are used by Everviz and
are not changed. The dw_ files have:
- the value column under a fixed name without the year (e.g. "Andel aleneboende"), with one decimal, so the
  maps keep working when the year changes (the map settings refer to the column by name)
- "Label+Value": shares rounded to a whole number with "%" ("Skien<br>41%"). Other values with no unit:
  one decimal (decimal comma) if the largest value in the data set is 10 or lower ("Bamble<br>1,7"),
  otherwise a whole number ("Bamble<br>353"). The tooltip shows the value column with one decimal.
- "Data_fra_aar": the year or period of the data (e.g. "2026" or "2022-2026") in every row, for custom text
  (in tooltips: {{ data_fra_aar }})


// Map
Municipalities in Telemark (custom basemap, from the repo file Kart/Kartfiler/Datawrapper_kommuner_Telemark.json).


// Colors
Color type: steps (the value range is split into equally wide intervals).
The number of steps is given per map (in the Excel file for batch creation): 5 or 3.
Standard: 5 steps, colors from light to dark:

 1  #f6efd5
 2  #f0e1bd
 3  #e0c58e
 4  #d4b67c
 5  #c7a869

Municipalities with missing data: grey. This is Datawrapper's default (light grey, label shows the name only;
checked 2026-11-10 with dw_bor_trangt.csv, where Tokke and Vinje are empty), so nothing has to be set.
The dw_ files keep missing values empty (not 0), so they are shown as missing.

Other numbers of steps (e.g. 4): colors evenly spread from the lightest (#f6efd5) to the darkest (#c7a869)
of the 5 colors, interpolated along the 5-color scale; the colors in between are calculated.
4 steps: #f6efd5, #ebd8ad, #d8bb82, #c7a869

With 3 steps:

 1  #f0e1bd
 2  #e0c58e
 3  #c7a869


// Labels
Map labels: the column "Label+Value" (municipality name and value on two lines).
Always show all labels, also where they overlap ("Prevent label overlapping" off).


// Legend
Color legend at the top right, inside the map, vertical, showing the value range of each step (e.g. "36%–44%").
No legend title.


// Text (title, intro, source, notes)
Data source ("Kilde"): deduced from the query script that fetches the data.
- SSB: name "SSB", link "https://www.ssb.no/statbank/table/XXXXX" with the SSB table used in the script
  (e.g. https://www.ssb.no/statbank/table/08113). If the script uses several tables, use the first.
  If the table number is only known when the script runs, use the SSB link in sources.csv.
- No direct link to a specific table in the script (e.g. FHI, IMDi, Utdanningsdirektoratet): use the source
  name and link listed in sources.csv (Migrering/sources.csv, one "name,url" per line). Sources not in that
  file: name only, link empty.
- If the script reads its URL from a query file (.txt, as the FHI scripts do), use the URL in that file.
Alt text: "Graf utarbeidet av Telemark fylkeskommune".


// Number format
If the name of the value column in the CSV or the title (from the Excel file, if supplied) contains "Andel",
use percentage formatting: "XX,X %" in tooltips (always one decimal, e.g. "41,5 %") and "XX%" in the legend.
Values that are not shares: no unit; tooltips with up to one decimal.
Map labels: shares rounded to the nearest whole number (from "Label+Value", see Data layout).
Legend: shares as whole numbers ("< 35%", "41%–44%"); other values with up to one decimal ("1,5–1,7").
Never two decimals.
Steps: Datawrapper's default "Linear (equi-distant)".
Decimals are always shown with a comma ("1,6"), also in tooltips.
The values in the map labels come from the "Label+Value" column as they are written in the CSV.


// Tooltips
Title: the municipality name. Body: the value ("XX %" for shares, see above).


// Footer
"Last ned data": enabled (links to Datawrapper's own copy of the data)
"Embed": enabled
"Last ned bilde": enabled
Other download options (PDF, SVG) and the logo: off


// Other
Language: Norwegian (nb-NO).

//// PART 2: TECHNICAL REFERENCE (from 3SHpp)

//// Chart level (top level, not under "metadata")

type        "d3-maps-choropleth"
language    "nb-NO"          (Norwegian number format: decimal comma, space as thousands separator)
theme       "datawrapper"

The basemap is a custom upload, stored with each chart as the asset "<chart id>.map.json" (TopoJSON).
Setting the basemap keys alone is not enough: the map is empty and the PNG export fails (tested 2026-11-09).
A new map needs the file uploaded:
  PUT /v3/charts/{id}/assets/{id}.map.json   (body: the TopoJSON, Content-Type application/json)
The file: https://raw.githubusercontent.com/evensrii/Telemark/refs/heads/main/Kart/Kartfiler/Datawrapper_kommuner_Telemark.json
(TopoJSON, object "Kommuner-S", 17 municipalities with the property "name"; identical to 3SHpp's asset,
checked 2026-11-09).
(Copying 3SHpp with POST /v3/charts/3SHpp/copy also works, but brings 3SHpp's leftover settings along.)


//// metadata.data (data source)

upload-method          "external-data"   (live: Datawrapper fetches the CSV from the URL itself)
external-data          <raw GitHub URL to the CSV>
use-datawrapper-cdn    true              ("Last ned data" points to Datawrapper's own copy)
transpose              false
horizontal-header      true
vertical-header        true
column-format          {"<value column>": {"type": "number"}, "Region": {"type": "text"},
                        "Label": {"type": "text"}}   (set by Datawrapper; no need to set it)

After setting the data source: POST /v3/charts/{id}/data/refresh to fetch the data immediately.
Datawrapper only refreshes the data automatically after the chart has been published once.

//// metadata.visualize: colors

colorscale.mode           "discrete"      (editor: Type = "Steps"; "Continuous" would be another value)
colorscale.stops          "equidistant"   (editor: Steps dropdown = "Linear (equi-distant)")
colorscale.interpolation  "equidistant"
colorscale.stopCount      5               (editor: Steps = 5; 3 with three colors)
colorscale.colors         5 steps:
                          [{"color": "#f6efd5", "position": 0},
                           {"color": "#f0e1bd", "position": 0.25},
                           {"color": "#e0c58e", "position": 0.5},
                           {"color": "#d4b67c", "position": 0.75},
                           {"color": "#c7a869", "position": 1}]
                          3 steps:
                          [{"color": "#f0e1bd", "position": 0},
                           {"color": "#e0c58e", "position": 0.5},
                           {"color": "#c7a869", "position": 1}]
                          (3SHpp has 0.4928 for the middle color, dragged in the editor; use 0.5)
colorscale.palette        1
colorscale.rangeMin/Max   ""              (min and max taken from the data)
colorscale.customStops    [null, 36, 44, 52, 60, null, "", "", ""]   (left over in 3SHpp; only used
                                           when stops is "custom")
colorscale.map            {}              (only used for category colors)

//// metadata.visualize: labels

labels.enabled            true
labels.type               "column"        (labels from a data column, see axes.labels)

                                           type is "column")

//// metadata.visualize: legend

legends.color.enabled       true
legends.color.position      "inside-right-top"
legends.color.orientation   "vertical"
legends.color.labels        "ranges"      (each step shows its interval, e.g. "36%–44%")
legends.color.labelFormat   "0%"          (in 3SHpp. Rule: "0%" if the value column or title contains "Andel"
                                           (whole numbers), otherwise "0,0.[0]" (up to one decimal, never two).
                                           Not "auto": that is not a valid format and shows "2." etc. Shows the value
                                           as written with % appended: 60 is shown as "60%")
legends.color.titleEnabled  false
legends.color.title         "<value column>"
legends.color.size          300
legends.color.reverse       false
legends.color.interactive   true
legends.pattern / combined  defaults (patterns are off)


//// metadata.visualize: tooltips

tooltip.enabled   true
tooltip.title     "%REGION_NAME%"
tooltip.body      "%REGION_VALUE% %"    (in 3SHpp. %REGION_VALUE% shows the raw value with a decimal point ("1.6").
                                         Rule for shares ("Andel" in the value column or title):
                                         '{{ FORMAT(<column variable>, "0.0") }} %' (always one decimal).
                                         Other values: '{{ FORMAT(<column variable>, "0.[0]") }}' (up to one decimal).
                                         If the CSV has "Data_fra_aar": tooltip.title
                                         '{{ <region column variable> }} ({{ data_fra_aar }})', e.g. "Vinje (2026)"
                                         (otherwise "%REGION_NAME%"); the body is only the value.
                                         Also metadata.data.column-format {"Data_fra_aar": {"type": "text"}}
                                         (otherwise "2026" is read as a date and shown as
                                         "Thu Jan 01 2026 00:00:00 GMT+0100 ...").
                                         Data placeholders only work in tooltips, not in the intro or
                                         notes (tested 2026-11-09: shown as literal text).
                                         <column variable> is the value column name in lowercase, spaces replaced
                                         by "_", special characters (also æ, ø, å) removed, e.g.
                                         "Forsørgerevne (2026)" -> forsrgerevne_2026,
                                         "Andel flyktninger 2025" -> andel_flyktninger_2025)
tooltip.sticky    true
